# ImageLab - Assessment 1

Go, PostgreSQL, HTML, CSS, and vanilla JavaScript. This repository currently contains the Week 1 acceptance foundation.

## Phase 1 implemented behavior

- Initial, selected-image, and uploading UI states based on the supplied screenshots
- Local preview without uploading
- JPEG/PNG decoding and authoritative 10 MB server limit
- Server-generated names under `storage/originals`
- PostgreSQL image, job, and variant schema
- Durable image metadata after original storage
- Disabled button plus `isSubmitting` protection

The job tables are prepared by the migration, but job creation, `202 Accepted`, worker processing, variants, and polling are intentionally deferred to later phases.

## Responsibility boundaries

- Browser: owns the unsubmitted file preview and sends one guarded upload. Job observation is added in Phase 3.
- API: validates the upload, safely stores the original, and persists the image metadata. Queued-job creation starts in Phase 2.
- PostgreSQL: owns authoritative image metadata, job state, timestamps, errors, and variant metadata.
- Worker: planned for Phase 2; no worker runs during Phase 1.
- Filesystem: stores original and generated bytes under server-controlled names.

## Setup

```bash
createdb imagelab
export IMAGELAB_DB_DSN='postgres://USER:PASSWORD@localhost/imagelab?sslmode=disable'
psql "$IMAGELAB_DB_DSN" -f migrations/000001_create_imagelab.up.sql
go run ./cmd/api -db-dsn="$IMAGELAB_DB_DSN"
```

Open <http://localhost:4000>.

The server must be started from the repository root so it can find `web/` and the default `storage/` directory. PostgreSQL must already be running. A successful Week 1 upload returns `201 Created`; the required queued job and `202 Accepted` response belong to Week 2.
